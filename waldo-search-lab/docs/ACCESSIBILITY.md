# Accessibility

This file covers the shipped page `dist/index.html`. It loads `app.js` (the game),
`clipart-cast.js` (decorative figures) and `qnn-playground.js` (the embedded QNN
playground, generated by `playground-integration/build.mjs`). We target WCAG 2.2 AA. The
"How we verified" section lists what was checked automatically and what still needs a
manual check.

## Features

**Structure**
- `<html lang="en">`, a descriptive `<title>`, and `header` / `nav` / `main` / `footer` landmarks.
- A "Skip to the search" link is the first focusable element.
- The page has one `h1`. The playground's column headings (`h4` in the upstream markup) carry
  `aria-level="3"`, so the outline goes h1 → h2 → h3.
- The game's legacy engine bindings live in a container that is `hidden`, `inert` and
  `aria-hidden`, so they never reach assistive technology or the tab order.

**Images and canvases**
- The Wanda portrait has meaningful alt text. Scene thumbnails use `alt=""` because the button
  already has a name ("Choose Festival", …). The drag preview and every clip-art bystander are
  decorative: the clip-art layer is `aria-hidden` and `inert`.
- The scene canvas is `role="application"` with an `aria-label`, and `aria-describedby` points to
  screen-reader instructions in `#canvas-instructions`. The playground's scene canvas is also
  `role="application"`, has its own label, and reports the inspected region in a polite live region.
- The playground's colour-scale SVG is `role="img"` and labelled by its caption. Its decorative
  callout arrows are `aria-hidden`.

**Names and labels**
- Every button, select and input has an accessible name. Icon-only playground buttons
  (add/remove layer) have `aria-label`s, and title-only selects (Grover grid, Wanda height) now
  have `aria-label`s.
- The hidden world `<select>` is named "Pick a world", which matches its visible step label
  "01 / PICK A WORLD" (WCAG 2.5.3). It becomes visible when it has keyboard focus.
- Arrow glyphs in links (↗ ↓) are `aria-hidden`, so screen readers don't announce them.

**Status messages (WCAG 4.1.3)**
- `#search-announcer` (`role="status"`, polite) announces search progress and results, for
  example "Found Wanda. Measured point …".
- Keyboard moves, **Shuffle placement** and **Remove Wanda** also announce Wanda's position in
  words and coordinates (for example "Wanda is in the middle right of the scene, at x 416, y 300
  of 512."), so the canvas is not the only feedback.
- The playground's search banner and region inspector are polite live regions. The epoch
  counter is deliberately not live, to avoid constant announcements.

**Motion**
- `prefers-reduced-motion: reduce` is honoured in the game. Grover rounds jump straight to the
  final state, the scene fade-in is skipped, the dragged Wanda doesn't swing
  (`stepDragPendulum({reducedMotion})`), CSS transitions and smooth scrolling are turned off,
  and the loading spinner stops.
- The game's internal reduced-motion toggle (`#circuit-reduce-motion`) is part of the hidden
  legacy explainer bindings and can't be reached on the current page. The OS setting is the
  control that applies.
- In the playground, the Grover animation checks the same media query. CSS animations and
  transitions are reduced to near zero by a rule in `playground-integration/theme.css`.

**Focus**
- Every focusable control in the game and the playground shows a 3px `:focus-visible` outline.
- Upstream playground rules had removed the outline from selects and from the
  Move target / Random spot / Regenerate buttons. A higher-priority rule in `theme.css` restores it.

**Colour contrast**
- Muted footer and header text was 4.49:1. The `--muted` token was darkened by two levels
  (`#69737a` → `#67717a`) to 4.61:1.

**Reflow**
- No horizontal page scroll at 320px and 640px viewport widths.

## Keyboard controls

| Where | Key | Action |
| --- | --- | --- |
| Anywhere | Tab / Shift+Tab | Move between controls (no keyboard traps) |
| Wanda's portrait | Enter / Space | Pick Wanda up; focus moves to the scene |
| Scene (Wanda picked up) | Enter | Place Wanda at her last position (centre right by default) |
| Scene (Wanda placed) | Arrow keys | Move Wanda 2px; hold Shift for 12px |
| Scene | Enter | Run the quantum search (Find Wanda) |
| Scene | Escape | Stop a running search, cancel a drag, or (before she is placed) cancel the pick-up and return focus to her portrait |
| Scene thumbnails / buttons | Enter / Space | Choose a world, find, shuffle, remove, start over, toggle the heat map |
| Playground scene | Arrow keys | Inspect a region's quantum state (announced) |

Dragging is never required. Wanda can be placed by keyboard, as above, or with a single tap or
click: tap the portrait, then tap the scene (WCAG 2.5.7).

## How we verified (October 2026)

- **axe-core 4.10.2 in headless Chrome** (puppeteer-core), with the WCAG 2.0/2.1/2.2 A/AA and
  best-practice rule sets. It covered the open shadow DOM and ran on desktop (1280×900), on
  mobile (390×844) with reduced motion, and on the playground's "Show all details" view.
  - Before the fixes: colour contrast (5 nodes), heading order, title-only labels (2), unnamed
    buttons (2), aside nested in a landmark, and skip link outside a landmark.
  - After the fixes: only the best-practice `region` notice for the skip link remains (see
    limitations). The WCAG 2.2 `target-size` rule passed.
- **Scripted keyboard walk.** About 70 Tab presses through the game and the playground, plus a
  full walk of the playground's details view. Every stop received a visible outline (69/69 in
  the details view). Before the fixes, Move target and Random spot had none.
- **Scripted keyboard placement.** Portrait → Enter → Enter → Arrow keys → Enter places Wanda,
  announces her position, runs the search and announces "Found Wanda".
- **Visual regression.** Above-the-fold screenshots before and after the changes differ only
  by colour deltas of at most 2 levels (from the `--muted` adjustment).
- **Unit tests.** `node --test tests/`: 147/147 pass before and after, with `@napi-rs/canvas`
  installed.

## Known limitations

- **No real screen-reader testing.** We haven't tested with VoiceOver, NVDA or JAWS.
  Announcements were checked only as DOM text in the live regions.
- **The canvas has only a general text alternative.** The crowd picture is described in general
  terms. Individual people aren't described, and the heat-map overlay is visual only. The search
  result, the measured point and the status text carry the same information as text.
- **Contrast of canvas content and of text over images or gradients was not measured**, because
  axe can't evaluate it.
- **Some playground graphics are hard to use without sight.** The network diagram, gate hover
  cards and charts are drawn by the bundled D3 engine (`assets/qnn-playground/engine.js`, a
  generated minified bundle we didn't modify). Gates are focusable and labelled ("Gate on qubit
  N, layer L"), but the diagram's wiring and the Bloch-sphere drawings have no complete text
  equivalent. D3's JavaScript transitions don't check reduced motion.
- **Skip link outside a landmark.** axe's best-practice `region` rule flags the skip link because
  it sits before the header landmark. That is the conventional position, and we left it there on
  purpose.
- **The playground's h4 headings are exposed as level 3 with `aria-level`** rather than by
  renaming the elements, so the upstream CSS keeps working.
- **Legacy explainer modules aren't loaded.** `underhood.js`, `quick-tour.js` and
  `oracle-quality.js` (with `grover-guide.js`, `measurement-view.js`, `circuit-playback.js` and
  `drawing-layout.js`, which `underhood.js` uses) aren't loaded by the current page. We didn't
  audit their runtime UI.
